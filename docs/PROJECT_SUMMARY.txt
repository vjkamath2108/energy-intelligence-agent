═══════════════════════════════════════════════════════════════════════════════
THE PROBLEM
═══════════════════════════════════════════════════════════════════════════════

Energy dispatch tools face a fundamental design challenge:

❌ Rigid rule engines: Cannot adapt to regulatory changes without code rewrites
❌ Unauditable ML systems: Cannot explain decisions to regulators
✅ Required: Adaptive, auditable, grounded recommendations

Energy market regulations change monthly. Fine-tuning LLMs monthly is 
impractical. The system needs RAG: retrieve current regulatory documents 
to ground recommendations without retraining.


═══════════════════════════════════════════════════════════════════════════════
THE SOLUTION
═══════════════════════════════════════════════════════════════════════════════

A RAG system that replaces rules engines with document retrieval + LLM reasoning.

ARCHITECTURE:

  1. RETRIEVAL LAYER
     - Hybrid search: BM25 (keyword) + semantic (embeddings) + RRF
     - pgvector for vector storage (atomic transactions with audit log)
     - A/B testing framework to measure retrieval quality
  
  2. GENERATION LAYER
     - Claude 3.5 Sonnet with structured JSON output
     - Grounding: every recommendation cites retrieved documents
     - Single-pass generation (orchestration-ready but not multi-step)
  
  3. SAFETY LAYER
     - Hallucination detection: flag contradictions with context
     - Confidence scoring: raw Claude output with audit logging
     - Immutable audit trail for regulatory compliance
     - Constraint validation: check recommendations against extracted rules

TECHNOLOGY:
  - Python 3.11+ (type-safe, mypy --strict)
  - PostgreSQL 15 + pgvector (RDS managed)
  - Pydantic v2 (schema validation, immutability)
  - LangChain (retrieval orchestration)
  - Claude 4.5 Sonnet (structured output, improved reasoning)
  - Langfuse (observability: traces, metrics)


═══════════════════════════════════════════════════════════════════════════════
KEY DESIGN DECISIONS
═══════════════════════════════════════════════════════════════════════════════

1. HYBRID RETRIEVAL (not pure semantic)
   Rationale: Energy domain contains domain-specific terminology that pure 
   semantic search misses. BM25 captures exact matches; semantic captures intent.
   Trade-off: Single approach simplicity vs measurement complexity

2. pgvector (not Pinecone/Chroma)
   Rationale: Atomic transactions between retrieval and audit data in same DB.
   Trade-off: Open source operational complexity vs vendor lock-in

3. Single-Pass Generation (not agentic loop)
   Rationale: Simplicity sufficient. Validation catches unsafe outputs.
   Trade-off: Single path simplicity vs multi-step refinement capability

4. Raw Confidence Scoring (not calibrated)
   Rationale: Claude output usable immediately. Infrastructure for calibration 
   in place if needed post-deployment.
   Trade-off: Speed to deployment vs confidence validity measurement

5. Structured Output Validation (safety-critical)
   Rationale: Pydantic v2 ensures well-formed recommendations before Claude.
   Trade-off: Strict schema enforcement vs flexibility

═══════════════════════════════════════════════════════════════════════════════
MEASUREMENT POINTS
═══════════════════════════════════════════════════════════════════════════════

Retrieval Quality:
  - A/B test: BM25 vs semantic vs hybrid
  - Metric: Precision@5 on evaluation set

Generation Quality:
  - All outputs properly grounded (cite sources)
  - Structured output validation

Safety:
  - Hallucination detection catches contradictions
  - Audit trail complete and immutable
  - Constraint validation working

Performance:
  - Retrieval + generation latency <2s (p95)
  - Code: mypy --strict, 80%+ coverage


═══════════════════════════════════════════════════════════════════════════════
WHAT THIS SYSTEM DOES NOT INCLUDE
═══════════════════════════════════════════════════════════════════════════════

- Multi-step agentic reasoning (infrastructure ready, not implemented)
- Confidence score calibration via Brier score validation
- Prompt optimization via A/B testing multiple templates
- Fine-tuning on domain-specific data
- Real-time model retraining

These are deferred for post-deployment phases or if time permits.
