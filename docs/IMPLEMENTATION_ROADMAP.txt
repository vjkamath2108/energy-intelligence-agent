INTERVIEW NARRATIVE (post-project):

"I built Energy Intelligence Agent as a production-grade RAG system. Here's why
each decision mattered:

• RAG over fine-tuning: Regulations change monthly. RAG lets us update docs
  without retraining. Fine-tuning would lock us in.

• pgvector over Pinecone: I wanted to avoid vendor lock-in and understand the
  trade-offs. pgvector + PostgreSQL is open-source, portable, and I can optimize
  the indexing strategy myself.

• Hybrid retrieval: Pure semantic search misses domain terminology in regulations
  ("peak demand response" isn't captured by embeddings alone). BM25 excels at
  phrase matching. RRF combines both strategies.

• Confidence scoring: Every recommendation includes a confidence score calibrated
  on a validation set. If <60%, the system escalates to human review. This is how
  you build trust in safety-critical systems.

• Audit trail: Every decision is logged with full context. An auditor can trace
  exactly why a recommendation was made. This matters for regulated domains.

• Python: This was my exercise in production-grade code. Type hints throughout,
  async/await for I/O, proper error handling, 80%+ test coverage. The code
  reflects standards I expect at Anthropic.

The most interesting challenge was hallucination detection. Simple approach: check
if recommendation terms appear in retrieved context. Production approach: semantic
similarity. I documented both and chose the pragmatic trade-off.

What I learned: RAG is not 'just embeddings' — it's about choosing the right
retrieval strategy, grounding outputs, and designing for safety from day one."
