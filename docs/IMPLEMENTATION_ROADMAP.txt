WEEK 1: Setup + Data Pipeline Foundation
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 
Goal: RDS PostgreSQL 15 + pgvector running with synthetic energy data loaded
 
CODING TASKS:
  ✓ Task 1.1: RDS PostgreSQL setup
    - AWS Console: Create RDS instance (PostgreSQL 15, db.t3.micro)
    - Enable pgvector extension: CREATE EXTENSION vector;
    - Security group: Allow inbound on port 5432 from your IP
    - Connection: Test with psql, store credentials in .env
    - Script: src/db.py (connection module)
    - Learning: AWS RDS management, connection pooling, credential handling
 
  ✓ Task 1.2: Data models (Pydantic v2)
    - RetrievedDocument, DispatchRecommendation, AuditLogEntry
    - LogEvent, AnomalyResult, Explanation (streaming layer models)
    - Type hints (not Optional, use | None notation)
    - Frozen=True for immutability in safety-critical path
    - Script: src/models.py
    - Learning: Pydantic schema design, type safety, validation
 
  ✓ Task 1.3: Document ingestion pipeline
    - Load synthetic energy docs (regulations, tariffs, historical decisions)
    - Implement semantic chunking (split at regulatory boundaries)
    - Show trade-off analysis: semantic vs fixed-size vs sliding window
    - Script: src/data_pipeline/ingest.py
    - Learning: LLM-friendly chunking, document structure preservation
 
  ✓ Task 1.4: Streaming layer skeleton
    - Synthetic EKS/telemetry log generator (50 events, mixed INFO/WARN/ERROR)
    - asyncio file tail consumer → internal queue
    - Script: src/streaming/log_generator.py + tail_consumer.py
    - Learning: asyncio patterns, event-driven pipeline foundations
    - Note: This runs in parallel with RAG foundation, not after it
 
DELIVERABLES:
  - RDS PostgreSQL 15 instance running + pgvector extension enabled
  - .env file with database credentials (DO NOT COMMIT)
  - src/db.py connection module (tested with RDS endpoint)
  - Pydantic model files with docstrings and validation rules (RAG + streaming)
  - Chunking pipeline with A/B test framework (compare 3 strategies)
  - Synthetic dataset: ~100 documents (regulations, customer data, market data)
  - Streaming skeleton: log generator + asyncio consumer running

WEEK 2: Vector Embedding + Retrieval + Anomaly Detection
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 
Goal: BM25 + semantic search working with evaluation framework;
      Isolation Forest anomaly detection running on streaming events
 
CODING TASKS:
  ✓ Task 2.1: Embedding & pgvector storage
    - OpenAI Embeddings API (or Bedrock Titan embeddings)
    - Store embeddings in pgvector with HNSW indexing
    - Batch API calls (async, efficient)
    - Script: src/retriever/embeddings.py
    - Learning: Embedding normalisation, efficient batch processing
 
  ✓ Task 2.2: BM25 search (PostgreSQL tsvector)
    - Full-text search config: English dictionary, phrase search
    - Query expansion for domain terms
    - Script: src/retriever/bm25_search.py
    - Learning: PostgreSQL full-text search, query normalisation
 
  ✓ Task 2.3: Hybrid retriever (HybridRetriever class)
    - Semantic search using pgvector (async)
    - BM25 search (async)
    - Reciprocal Rank Fusion (RRF) to combine rankings
    - Document why RRF matters (semantic misses domain terms, BM25 misses intent)
    - Script: src/retriever/hybrid_retriever.py
    - Learning: Ranking fusion, why multiple strategies matter
 
  ✓ Task 2.4: Retrieval evaluation framework
    - Synthetic test set: 10–15 queries with ground truth answers
    - Metrics: Precision@K, NDCG, hit rate, latency
    - A/B test: BM25 only vs semantic only vs hybrid
    - Script: eval/retrieval_evals.py
 
  ✓ Task 2.5: Isolation Forest anomaly scorer
    - Features: latency_ms, error flag (ERROR level), status_code
    - Buffer 20 events before fitting, then score each new event
    - Windowed batch scoring (10s rolling window)
    - Script: src/detection/anomaly_scorer.py
    - Learning: Isolation Forest contamination tuning, online/batch trade-off
 
  ✓ Task 2.6: Redis Streams upgrade for ingestion
    - Replace file tail with Redis Streams (XADD/XREAD pattern)
    - Keep file tail as --mode file fallback
    - Script: src/streaming/redis_consumer.py
    - Learning: Redis Streams consumer groups, backpressure handling
 
DELIVERABLES:
  - HybridRetriever class (fully typed, async)
  - pgvector schema + indexes (HNSW, L2 distance)
  - Evaluation results: table showing hybrid > any single strategy
  - VECTOR_DB_ANALYSIS.md: pgvector vs Pinecone vs Chroma comparison
  - AnomalyScorer class with configurable contamination threshold
  - Redis Streams consumer running alongside file tail fallback
 
CHECKPOINT:
  [ ] python -m pytest tests/test_retriever.py -v
  [ ] Retrieval latency < 500ms (p95)
  [ ] Hybrid Precision@5 ≥ 0.7
  [ ] A/B test results documented
  [ ] Anomaly scorer detects injected spike (5xx errors) within 2 windows
  [ ] Redis Streams consumer reading events correctly
 
LEARNING FOCUS:
  - Async I/O patterns: asyncio.gather, concurrent requests
  - Ranking algorithms: TF-IDF, BM25, RRF math
  - Vector distance metrics and index structures
  - Isolation Forest: contamination, feature engineering on event data

WEEK 3: Claude Integration + Recommendation + Explanation Engines
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 
Goal: Claude generating grounded dispatch recommendations;
      Bedrock Claude generating anomaly explanations on detected events
 
CODING TASKS:
  ✓ Task 3.1: Claude API wrapper with structured output
    - Bedrock endpoint: anthropic.claude-sonnet-4-5 (model string: claude-sonnet-4-5)
    - Messages API with system + user prompts
    - Force grounding: "You MUST cite which documents support this recommendation"
    - Structured output (JSON schema) for DispatchRecommendation
    - Retry logic for rate limits (exponential backoff)
    - Script: src/recommendation_engine/claude_client.py
    - Learning: Bedrock invocation patterns, structured output
 
  ✓ Task 3.2: Anomaly explanation layer
    - Bedrock Claude called when anomaly score crosses threshold (-0.3)
    - Input: anomaly event + surrounding ±5 events as context
    - Output: Explanation — { severity, summary, likely_cause, recommended_action }
    - Retry on invalid JSON output (Pydantic validation + reprompt)
    - Script: src/explanation/bedrock_explainer.py
    - Learning: Chain-of-thought prompting for incident explanation
 
  ✓ Task 3.3: Ollama explainer as drop-in replacement
    - OllamaExplainer class with identical interface to BedrockExplainer
    - CLI flag: --explainer bedrock|ollama
    - Same Explanation Pydantic schema regardless of backend
    - Script: src/explanation/ollama_explainer.py
    - Learning: Abstraction patterns, dependency injection, local inference
 
  ✓ Task 3.4: Prompt engineering & grounding
    - System prompt that enforces citation of context
    - Few-shot examples: good dispatch recommendation vs hallucinated
    - Script: src/recommendation_engine/prompts.py
 
  ✓ Task 3.5: Hallucination detection
    - Simple: check if recommendation terms appear in retrieved context (≥30%)
    - Production: semantic similarity check using embeddings
    - Flag for human review if hallucination likely
    - Script: src/recommendation_engine/safety.py
 
  ✓ Task 3.6: Recommendation + explanation engine tests
    - Test: Claude generates action grounded in context
    - Test: Hallucination detection catches contradictions
    - Test: Bedrock and Ollama produce same schema
    - Script: tests/test_recommendation_engine.py + tests/test_explanation.py
 
DELIVERABLES:
  - RecommendationEngine class (fully typed, async)
  - BedrockExplainer + OllamaExplainer (identical interface, swappable)
  - Prompt templates (system, user examples)
  - Hallucination detection logic with configurable threshold
  - Test suite covering edge cases
 
CHECKPOINT:
  [ ] python -m pytest tests/test_recommendation_engine.py -v
  [ ] python -m pytest tests/test_explanation.py -v
  [ ] All recommendations properly typed as DispatchRecommendation
